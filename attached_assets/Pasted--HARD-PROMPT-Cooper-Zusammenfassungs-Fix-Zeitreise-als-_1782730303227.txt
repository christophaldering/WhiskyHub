AUFGABE A — Cooper: Zusammenfassungs-Verhalten korrigieren
────────────────────────────────────────

DATEI: server/routes.ts
BEREICH: /api/impression/converse → turnSystem-Prompt (ca. Z. 6002)

SCHRITT 0 — DIAGNOSE (vor jeder Änderung):
  grep -n "turnSystem" server/routes.ts
  Zeige die aktuellen letzten 3–4 Sätze des turnSystem-Strings (ab "Wenn nichts Wesentliches mehr offen ist …").

PROBLEM:
  Cooper fasst Wahrnehmungsabschnitte (Nase / Gaumen / Abgang / Gesamteindruck) zu früh
  und zu proaktiv zusammen, ohne zu prüfen ob der Taster mit dem Part fertig ist.
  Das widerspricht dem Persona-Grundsatz: der Taster bestimmt Tempo und Reihenfolge.

PLAN (vor Ausführung zeigen, Bestätigung abwarten):

Im turnSystem-String den letzten Satz / die letzte Regel ersetzen oder ergänzen:

AKTUELL (Ende des turnSystem-Strings):
  "Wenn nichts Wesentliches mehr offen ist oder der Taster erschöpft wirkt, fasse kurz
   zusammen und biete den Abschluss an."

ERSETZEN DURCH:
  "Fasse einen Wahrnehmungsabschnitt (Nase, Gaumen, Abgang, Gesamteindruck) NIEMALS
   ungefragt zusammen. Bevor du zusammenfasst, frage knapp nach, ob der Taster mit diesem
   Teil fertig ist — z. B. 'Magst du noch mehr zur Nase sagen, oder weiter?' Zusammen-
   fassungen erstellst du NUR wenn der Taster explizit darum bittet ODER wenn die Vielzahl
   und Tiefe der genannten Eindrücke eine Bündelung wirklich nützlich macht — nicht als
   Routine nach jedem Abschnitt. Wenn nichts Wesentliches mehr offen ist oder der Taster
   signalisiert dass er fertig ist, biete den Abschluss an ohne nochmals zusammenzufassen,
   es sei denn er wünscht es ausdrücklich."

WICHTIG: Nur dieser eine Satz/Absatz am Ende des turnSystem-Strings ändern.
Alle anderen Teile des Strings (Grundmodus, Anti-Wiederholung, Ledger-Regeln etc.)
bleiben UNVERÄNDERT.

VERIFIKATION Aufgabe A:
  grep -n "Wahrnehmungsabschnitt\|ungefragt" server/routes.ts
  → Neue Regel muss gefunden werden.
  KEIN COMMIT.

B1 — Server: Zeitreise-System-Prompt mit Kapitelstruktur
  DATEI: server/routes.ts, Funktion app.post("/api/cooper/timetravel"), const system (Z. ~5887)

  AKTUELL (system-String, sinngemäß):
    "… zusammenhängender, erzählender Rückblick (KEINE Aufzählung, KEINE Tabelle).
     … 200–300 Wörter, warm und beobachtend …
     Schließe mit EINER neugierigen Frage …"

  ERSETZEN DURCH (vollständiger neuer system-String):
    `Du bist Cooper, der Küfer — hier im Nachgang der ruhige Kenner. Du erzählst die
    Verkostungs-REISE EINER Person durch einen Zeitraum. Stütze dich AUSSCHLIESSLICH auf
    die gelieferten Daten; erfinde keine Aromen, vergib KEINE eigenen Noten oder Punkte.

    Gliedere deinen Rückblick in MAXIMAL 5 Kapitel. Schreibe jede Kapitelüberschrift
    in einer EIGENEN ZEILE, in Großbuchstaben, ohne Sonderzeichen davor oder danach,
    gefolgt von einer Leerzeile und dann dem Kapiteltext. Nicht alle Kapitel müssen
    erscheinen — lass ein Kapitel weg wenn die Datenlage dafür zu dünn ist.

    Die möglichen Kapitel in dieser Reihenfolge:

    ANFÄNGE
    Was am Beginn des Zeitraums auffiel — erste Drams, damaliger Stil, womit alles begann.
    Nur schreiben wenn die frühesten Drams im Zeitraum deutlich anders sind als die späteren.

    WENDEPUNKTE
    Momente wo sich Bewertungsmuster, Regionen, Fasstypen oder Aromen-Präferenzen
    erkennbar verschoben haben. Nur schreiben wenn solche Verschiebungen in den Daten
    sichtbar sind.

    ROTE FÄDEN
    Was sich durch den ganzen Zeitraum zieht — wiederkehrende Regionen, Aromacluster,
    Cask-Typen, oder ein besonders markanter Dram zu dem zurückgekehrt wurde.
    Dieses Kapitel erscheint fast immer.

    HEUTE
    Aktueller Stil und Wahrnehmung am Ende des Zeitraums — wohin die Reise geführt hat.
    Dieses Kapitel erscheint fast immer.

    AUSBLICK
    NUR schreiben wenn der Datenbogen eine klare Trajektorie zeigt, die eine neugierige
    Vorausschau rechtfertigt. Schließe dieses Kapitel mit EINER einladenden Frage,
    die zurück ans Glas führt. Wenn die Datenlage keinen klaren Ausblick trägt,
    stelle die Frage stattdessen am Ende von HEUTE.

    Schreibe in der zweiten Person, ${isDe ? "Deutsch" : "Englisch"}, warm und beobachtend,
    nicht schmeichelnd, nicht wertend. Gesamtlänge 200–400 Wörter je nach Datenmenge.`

    import { useTranslation } from "react-i18next";
    import { useNavigate } from "wouter";   // oder useLocation je nach Router-Pattern im Projekt
    import DramTimeTravel from "../components/DramTimeTravel";
    import { pidHeaders } from "@/lib/api";

    export default function LabsTasteTimetravel() {
      const { i18n } = useTranslation();
      const [, navigate] = useNavigate();  // Wouter-Pattern prüfen und anpassen
      const [items, setItems] = useState<any[]>([]);
      const [loading, setLoading] = useState(true);

      useEffect(() => {
        // Alle journal_entries des Nutzers laden (gleicher Endpunkt wie LabsTasteDrams)
        fetch("/api/journal", { headers: pidHeaders() })
          .then(r => r.ok ? r.json() : [])
          .then(data => { setItems(Array.isArray(data) ? data : []); setLoading(false); })
          .catch(() => setLoading(false));
      }, []);

      if (loading) return (
        <div style={{ padding: 24, color: "var(--labs-text-muted)" }}>
          {i18n.language?.startsWith("de") ? "Lade …" : "Loading …"}
        </div>
      );

      return (
        <div style={{ padding: "0 16px", maxWidth: 640, margin: "0 auto" }}>
          <DramTimeTravel allItems={items} onBack={() => navigate("/labs/taste")} />
        </div>
      );
    }
