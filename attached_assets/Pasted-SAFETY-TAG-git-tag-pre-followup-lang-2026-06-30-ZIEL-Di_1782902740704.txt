ZIEL:
Die followUpQuestion im /api/impression/parse-Endpoint wird auf
Deutsch generiert, wenn der Eindruck knapp/deutsch ist — auch wenn
die App auf Englisch steht. Der Prompt sagt zwar "Antworte in der
Sprache des Eindrucks", aber bei kurzen Eingaben rät das Modell die
Sprache aus dem Text statt aus der App-Sprache. Fix: Client sendet
lang ("de"|"en") mit, Server gibt der Sprache explizit den Vorrang.

SCOPE: server/routes.ts (/api/impression/parse) +
client/src/labs/components/rating/impressionApi.ts (parseImpression).
Analog zum langDirective-Fix vom Voice-Endpoint heute. Keine
Schema-Änderung.

SCHRITT 0 — DIAGNOSE (nur lesen):
1. Zeige parseImpression in impressionApi.ts (Z.~45) vollständig —
   der fetch-Body. Wird lang bereits gesendet? (Nein erwartet.)
2. Zeige wie i18n in impressionApi.ts verfügbar ist / importiert
   werden muss (analog useCooperVoice.ts-Fix von heute:
   import i18n from "@/lib/i18n").
3. Zeige die parse-Endpoint system-content-Zeile mit "Antworte in
   der Sprache des Eindrucks" (Z.5552) — exakter Wortlaut für den
   Replace.
4. Bestätige: Der finalize-Pfad (converse, Z.6090) setzt followUp
   hart auf "" — dort ist KEINE Sprachänderung nötig (kein
   followUp generiert).

SCHRITT 1 — PLAN (bestätigen):
A) Client: parseImpression (impressionApi.ts)
   - import i18n from "@/lib/i18n" (falls nicht vorhanden)
   - const lang = i18n.language?.startsWith("de") ? "de" : "en"
   - lang im Body mitsenden:
     body: JSON.stringify({ text, whiskyName, askedQuestions, lang })
B) Server: /api/impression/parse
   - lang lesen: const lang = req.body?.lang === "en" ? "en" : "de"
     (Fallback "de")
   - Im system-content den Satz "Antworte in der Sprache des
     Eindrucks." ersetzen durch einen sprachexpliziten Befehl:
     lang === "en"
       ? "Answer in English. All text fields (nose, taste, finish,
          followUpQuestion) must be in English."
       : "Antworte auf Deutsch. Alle Textfelder (nose, taste,
          finish, followUpQuestion) müssen auf Deutsch sein."
     Als Template-Variable einsetzen, damit followUpQuestion
     zuverlässig in App-Sprache kommt.
   - WICHTIG: Der Rest des deutschen System-Prompts (die JSON-
     Struktur-Anweisung, SCORE-REGEL etc.) bleibt unverändert —
     das Modell versteht die Instruktion und liefert trotzdem
     Textfelder in der Zielsprache. Nur der eine Sprach-Satz
     wird dynamisch.
