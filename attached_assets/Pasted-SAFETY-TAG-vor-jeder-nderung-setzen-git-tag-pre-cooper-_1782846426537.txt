SCHRITT 1 — PLAN (zur Bestätigung vorlegen, NICHT ausführen ohne OK):

A) Neue Tabelle `landing_cooper_demo_log`:
   - ip_hash (text, sha256 der IP — oder bestehende Hash-Methode, falls 
     Diagnose eine andere ergibt)
   - day_key (text, Berlin-Zeitzone, Format YYYY-MM-DD)
   - count (integer, default 0)
   - last_run_at (timestamp)
   - PK aus (ip_hash, day_key)
   Additive Schema-Änderung. NACH Push: manuell `npx drizzle-kit push --force` 
   in Replit-Shell nötig — explizit im Verifikationsschritt erinnern.

B) Neuer Endpoint POST /api/public/cooper-demo/start (kein Auth):
   - IP aus Request ermitteln (Proxy-Header beachten, falls Replit dahinter), 
     hashen, day_key (Berlin) berechnen
   - Limit: 2 Starts pro IP pro Tag, Slot-Claim via INSERT ... ON CONFLICT 
     DO UPDATE (count erhöhen), analog Backup-Scheduler-Pattern
   - Bei Limit erreicht: 429 mit kurzer JSON-Message (z.B. 
     "Komm später wieder oder probiere CaskSense direkt aus")
   - Bei OK: ephemeral key für Realtime API ausstellen MIT serverseitig 
     erzwungenem Hard-Timeout (z.B. 75 Sekunden) — falls die Realtime API 
     selbst kein Session-Limit kennt, serverseitigen Watchdog/Timer bauen, 
     der die Session aktiv beendet, NICHT nur Client-seitig
   - Eigene, feste Demo-Persona-Instruction (separat von cooperLevel-Presets, 
     eigene kurze System-Instruction): Cooper stellt sich kurz vor, 
     beschreibt EINEN festen Beispiel-Dram, beantwortet maximal 1-2 
     Rückfragen, lädt am Ende ein, es mit dem eigenen Glas in der App 
     auszuprobieren. KEIN Ledger, KEIN Zugriff auf echte Whisky-/Nutzerdaten, 
     KEIN Tool-Calling.

C) Client-Flow:
   - Schwebender Button (fixed position, z.B. unten rechts) mit bestehendem 
     CooperBarrel-Icon auf der Landingpage
   - Klick → Erklär-Screen (kurz: was ist Cooper, KI-Stimmen-Offenlegung, 
     Hinweis auf Zeitlimit) → "Mikro freigeben & starten"-Button
   - Nach Freigabe: Call an /api/public/cooper-demo/start, bei 429 
     freundliche Fehlermeldung statt Connect-Versuch
   - Bei Erfolg: Realtime-Verbindung analog bestehendem useCooperVoice-Hook, 
     ggf. als eigene schlanke Variante (kein participantId, kein Ledger-State)
   - Sichtbarer Countdown/Hinweis während der Demo, dass sie zeitlich 
     begrenzt ist (vermeidet abruptes Abbrechen-Gefühl)

D) Kein neuer Eintrag in cooperLevel-Logik in routes.ts ~5612 — Demo-Pfad 
   bekommt eigene, getrennte Instruction-Konstante, um die bestehende 
   Persona-Steuerung nicht zu verwässern oder versehentlich zu beeinflussen.
