HARD PROMPT — whiskies.abv: Bruch-Werte (×100) korrigieren

KONTEXT: Manche whiskies.abv wurden als Anteil importiert (z.B. 0.52 statt 52). Diskriminator:
abv < 1 = falsch → ×100. abv >= 40 = korrekt, NICHT anfassen. Reine DB-Operation, eine Spalte.

ABSOLUTE VERBOTE (ganzer Lauf):
- KEIN git add/commit/push. KEINE Code-Datei. NICHT shared/schema.ts. KEIN drizzle-kit.
- NUR die SQL unten. Backup-Tabelle NICHT droppen. Nach Verifikation STOPPEN und berichten.
- Bei JEDER Abweichung von den Erwartungswerten: sofort STOPP, nicht "reparieren", nur berichten.

SCHRITT 0 — DIAGNOSE (read-only)
  SELECT
    count(*)                                        AS total,
    count(abv)                                      AS have_abv,
    count(*) FILTER (WHERE abv < 1)                 AS fraction_x100,   -- Kandidaten
    count(*) FILTER (WHERE abv >= 1 AND abv < 35)   AS suspicious_mid,  -- MUSS 0 sein
    count(*) FILTER (WHERE abv > 80)                AS suspicious_high, -- sollte 0 sein
    min(abv) AS min_abv, max(abv) AS max_abv
  FROM whiskies;

  -- Stichprobe der zu korrigierenden Zeilen (alt → neu):
  SELECT id, name, distillery, abv, round((abv*100)::numeric,1) AS abv_fixed
  FROM whiskies WHERE abv < 1 ORDER BY abv LIMIT 50;

ABBRUCH-BEDINGUNG: Wenn suspicious_mid > 0 ODER suspicious_high > 0 → STOPP, Werte berichten,
NICHT weitermachen (andere Fehlerklasse, braucht separate Behandlung).

────────────────────────────────────────
SCHRITT 1 — BACKUP (präziser Rollback)
  CREATE TABLE whiskies_abv_bak_20260628 AS
  SELECT id, abv FROM whiskies WHERE abv < 1;
  -- merke dir die Zeilenzahl = Anzahl Kandidaten aus Schritt 0 (fraction_x100)

────────────────────────────────────────
SCHRITT 2 — UPDATE
  UPDATE whiskies
  SET abv = round((abv * 100)::numeric, 1)
  WHERE abv < 1 AND abv IS NOT NULL;
  -- erwartet: UPDATE = fraction_x100
