## Checkpoint: "Frag CaskSense — Community-Benchmark-Tool" (29.04.2026)
Task #1191: Vergleichswerkzeug für „wie liege ich gegenüber dem CaskSense-Schnitt" mit Privacy-Opt-in.
- **Schema**: Neues Feld `profiles.share_stats_for_benchmarks` (boolean, default `false`) in `shared/schema.ts`. Startup-Migration in `server/index.ts` legt die Spalte idempotent an (`ALTER TABLE profiles ADD COLUMN IF NOT EXISTS share_stats_for_benchmarks boolean DEFAULT false`). Route `PUT /api/profiles/:participantId` akzeptiert `shareStatsForBenchmarks` boolean (typische `... in req.body`-Sentinel-Pattern wie die anderen Notif-Prefs).
- **Tool** `get_benchmark_stats` in `server/labs-ask-tools.ts`: gleicher Filter-Set wie `count_user_whiskies` (region/peat_level/distillery/min_score/max_score), aggregiert ratings nur über User mit `share_stats_for_benchmarks = true` (EXISTS-Subselect). Returnt `rating_count`, `contributing_users`, `distinct_whiskies`, `avg/min/max_score`, `top_regions_by_avg` (Region-Avg gefiltert auf >=3 Distinct Users). **K-Anonymity-Floor `MIN_BENCHMARK_USERS = 3`**: bei <3 zustimmenden Usern für den Filter wird `{ sufficient: false, contributing_users, message }` zurückgegeben — keine konkreten Zahlen leaken. Sources-Array bleibt leer (rein aggregierte Daten, keine Quellen-Chips).
- **System-Prompts** (DE+EN): Neuer „Vergleichs-Werkzeug"-Block weist die KI an, `get_benchmark_stats` mit denselben Filtern wie das passende Eigen-Statistik-Werkzeug aufzurufen und Vergleiche konkret zu phrasieren („Du liegst 4 Punkte über dem CaskSense-Schnitt"). Bei `sufficient: false` ehrlich sagen, dass kein Vergleich möglich ist.
- **Frontend** in `client/src/labs/pages/LabsTasteSettings.tsx`: Neuer „Privacy"-Block (BarChart3-Icon) im selben Account-Card unterhalb der Notifications-Sektion mit Checkbox „Share my stats for community benchmarks". Speichern via neuem `savePrivacyPref`-Callback (separater Saving-State `privacySaving`), nutzt bestehenden `profileApi.update`. Standardwert `false` — explizites Opt-in nötig. Beschreibender Hilfetext erklärt: nur Aggregate, nie Name/Notes/Einzel-Ratings, nur ab 3 matchenden Usern.
- **Verifikation** (live curl): Nach manuellem Setzen von `share_stats_for_benchmarks = true` für 3 Test-User und Frage „Wie hoch ist der durchschnittliche Score der CaskSense-Community insgesamt?" → KI antwortet exakt mit dem SQL-Aggregat (68.7 Punkte). Bei 0/2 zustimmenden Usern liefert das Tool `sufficient: false` und die KI berichtet ehrlich, dass kein Benchmark verfügbar ist. Test-Daten danach zurückgesetzt.

## Checkpoint: "Frag CaskSense — Statistik-Tools + Allgemeinwissen-Fallback" (29.04.2026)

## Checkpoint: "Frag CaskSense — KI-Chat mit Quellenkarten (KI-Suche Stufe 3)" (28.04.2026)
Task #1184: Die globale Labs-Suche (`client/src/labs/components/LabsGlobalSearch.tsx`) hat jetzt einen zweiten Modus „Frag CaskSense" — natürlichsprachlicher Chat mit gestreamten Antworten, gegroundet auf User-eigene Daten + öffentliches Lexikon/Distillerien.
- **Endpoint** `POST /api/labs/ask` in `server/routes.ts` (kurz vor den Admin-Embedding-Routen): Auth via `requireAuth(req)` (Header `x-participant-id`), Body Zod-validiert `{ question: 2..1000, locale, conversationHistory: max 20 Msgs à role+content<=8000 }`. In-Memory Rate-Limit `Map<participantId, number[]>` mit Rolling-Window 1h und Cap 30/Stunde (lokalisiertes 429 + retryAfterSec).
- **Hybrid-Retrieval** spiegelt `/api/labs/search`: parallele SQL-Branches für Whiskies + Tastings (gefiltert auf `tasting_id = ANY($::varchar[])` aus `storage.getTastingsForParticipant(participantId)`), Distilleries (Top 2, global) und Lexikon (Top 4, locale-filtered). Score = 0.6 × max(`ts_rank`×4, Trigram) + 0.4 × Cosine; Vector wird nur genutzt wenn `isEmbeddingAvailable()` und Query ≥3 Zeichen.
- **Streaming**: `aiResult.client.chat.completions.create({ model: "gpt-4o-mini", stream: true, signal: upstreamAbort.signal })` über `getAIClient(participantId, "labs-ask")` — Plattform-Key (`AI_INTEGRATIONS_OPENAI_API_KEY` via modelfarm) + User-Key + Quota-Check werden wiederverwendet. SSE-Format: `data: {"delta":"..."}\n\n` pro Chunk, terminiert mit `data: {"done":true,"sources":[...]}\n\n`.
- **System-Prompt** DE/EN: „Antworte ausschliesslich auf Basis der Quellen, erfinde nichts." + nummerierter Quellen-Block aus den Retrieval-Treffern (Format `[1] (WHISKY) Name — Subtitle\n    Snippet`).
- **Server-side Abort**: `req.on("close")` → `AbortController.abort()` wird via `signal` an die OpenAI-Streaming-Call übergeben, Loop bricht früh ab, `AbortError` wird stumm verschluckt — kein weiterer Token-Verbrauch nach Client-Disconnect.
- **Frontend** in `LabsGlobalSearch.tsx`: neuer Pill-Toggle „Suche" / „Frag CaskSense" direkt unter der Eingabe; im Chat-Modus ersetzt das Chat-Panel den Result-Bereich. Empty-State mit drei Suggestion-Chips. Streaming via `fetch().body.getReader()` + `TextDecoder`, Parser für SSE-Lines (`data: …`). Assistant-Bubbles bekommen Quellen-Chips mit Typ-Icon (Wine/Calendar/Building2/BookOpen), nummeriert, klickbar — Klick navigiert per wouter zu `/labs/explore/bottles/{id}`, `/labs/tastings/{id}?section=praesentation`, `/labs/discover/distilleries?focus={name}` oder `/labs/discover/lexicon?term={term}`.
- **Konversations-Kontext**: `chatMessages` lebt in der Modal-Session; Frontend und Backend trimmen beide auf die letzten 10 Msgs (Frontend `slice(-10)`, Backend `trimmedHistory = conversationHistory.slice(-10)`), damit Folgefragen Bezug nehmen können ohne den System-Prompt zu sprengen. Reset beim Schliessen des Modals.
- **Skalierungs-Hinweis**: Das Rate-Limit ist bewusst In-Memory (`Map<participantId, number[]>` pro Server-Prozess). Bei Restart wird der Counter zurueckgesetzt und das Limit gilt nur pro Replica — fuer den aktuellen Single-Instance-Deploy ausreichend. Wenn horizontal skaliert wird, sollte das Limit nach Redis (oder vergleichbar) ausgelagert werden.
- **Verifikation** (live curl): 401 bei fehlendem `x-participant-id`, 400 bei zu kurzer Frage, SSE-Stream liefert DE und EN Antworten zu „Was ist ein Octave?", „Tell me about peated whisky", „Was ist Sherry-Fass-Reifung?". Client-Abort via `timeout 1 curl` beendet den Server-Stream sauber ohne Error-Logs.
- **Status Embeddings**: Wie in Stufe 2 — `OPENAI_API_KEY` ohne Credits, modelfarm liefert Chat aber NICHT Embeddings, Retrieval läuft daher im FTS+Trigram-Modus. Sobald Credits da sind, wird Vector-Score automatisch dazugemischt.

## Checkpoint: "Labs-Globalsuche v2: Volltext + Tippfehler + Tastings + KI" (28.04.2026)
Task #1174: Die Labs-Suche (`client/src/labs/components/LabsGlobalSearch.tsx`) wurde von client-side `String.includes` auf eine echte hybride Server-Suche umgestellt.
- **Postgres-Infrastruktur**: `search_vector tsvector`-Spalten und die GIN-Indexe darauf sind in `shared/schema.ts` deklariert (`customType` namens `tsvector`). Die `gin_trgm_ops`-Trigram-Indexe sind dagegen NICHT im Schema, weil Replits Deploy-Migrator die Operator-Class beim Generieren verschluckt (`CREATE INDEX ... USING gin ("term")` ohne `gin_trgm_ops` → "data type text has no default operator class for access method gin"). Stattdessen werden alle 5 Trigram-Indexe (`idx_whiskies_name_trgm`, `idx_whiskies_distillery_trgm`, `idx_tastings_title_trgm`, `idx_distilleries_name_trgm`, `idx_lexicon_term_trgm`) ausschließlich von `server/search-init.ts` → `ensureIndexes()` mit korrekter Operator-Class via `CREATE INDEX IF NOT EXISTS ... USING GIN ("col" gin_trgm_ops)` beim Server-Start angelegt. `script/build.ts` ruft `CREATE EXTENSION IF NOT EXISTS pg_trgm/unaccent` in `preBuildMigrations` auf. `server/search-init.ts` ist insgesamt zuständig für: Extensions, Lexicon-Tabelle (defensives `CREATE TABLE IF NOT EXISTS`), search_vector-Spalten, Trigger-Funktionen, Whisky-→-Tasting-Refresh, Trigram-Indexe, Backfill der `search_vector`-Spalten, Seed der `lexicon`-Tabelle aus `client/src/labs/data/lexiconData.ts` (40 EN + 40 DE Begriffe). Die `embedding vector(1536)`-Spalten und `ivfflat`-Indexe wurden vorerst entfernt (OpenAI ohne Quota).
- **Schema** (`shared/schema.ts`): neue Tabelle `lexicon` (id/locale/category/term/definition/sortOrder, Unique-Constraint locale+term).
- **Embeddings-Helper** (`server/lib/embeddings.ts`): kapselt OpenAI `text-embedding-3-small` (Priorität: direkter `OPENAI_API_KEY`, sonst `AI_INTEGRATIONS_OPENAI_API_KEY`-Proxy); buildet pro Entity einen kompakten Text; `getQueryEmbedding` mit 5-min In-Memory-Cache; `fireAndForgetEmbed(table, id)` wird in `server/storage.ts` bei `createWhisky`, `updateWhisky`, `createTasting`, `findOrCreateDistilleryByName` aufgerufen.
- **Backfill-Skript** (`scripts/embed-backfill.ts`): batched (32) alle Rows mit `embedding IS NULL` durch OpenAI. Erfordert OpenAI-Quota; ohne Quota läuft die Suche sauber im Lex-Only-Modus weiter.
- **Endpoint** `GET /api/labs/search?q=&types=whisky,tasting,distillery,lexicon&locale=de|en&limit=N` in `server/routes.ts`: Hybrid-Score = 0.6 × max(`ts_rank` × 4, Trigram-Similarity) + 0.4 × Cosine-Similarity (vector). Visibility-Filter: Members (Admin oder mit Community) sehen alles; Gäste nur Tastings mit `visibility IN ('public','group')` + Status open/closed/reveal/archived und nur Whiskies dieser Tastings. Antwort: `{query, locale, embeddingUsed, counts:{whisky,tasting,distillery,lexicon}, results:[{type,id,title,subtitle,snippet,score,meta}]}`.
- **Frontend-Rewrite**: `LabsGlobalSearch.tsx` zieht alle vier Kategorien aus dem neuen Endpoint, behält die Pages-Registry client-seitig. Neue Gruppe „Tastings" mit Klick-Route `/labs/tastings/:id`. Distillery- und Lexicon-Routen bekommen jetzt einen Query-Hint (`?focus=` bzw. `?term=`). Kein Import von `@/data/distilleries` und `@/labs/data/lexiconData` mehr in der Suche.
- **Tasting-Index enthält Whisky-Namen**: Der `tastings.search_vector`-Trigger sammelt zusätzlich die Namen/Brennereien/Regionen der zugehörigen Whiskies (Sub-Select über `whiskies WHERE tasting_id = NEW.id`). Ein zweiter Trigger auf `whiskies` (AFTER INSERT/UPDATE/DELETE) feuert `UPDATE tastings SET title = title` auf das Parent-Tasting, damit dessen Vektor automatisch aktuell bleibt.
- **Robustheit**: `search-init.ts` legt die `lexicon`-Tabelle vor dem ALTER selbst defensiv an (`CREATE TABLE IF NOT EXISTS`), und jeder einzelne `ALTER TABLE`-Step ist eingeklammert, damit ein Fehler nicht alle anderen Tabellen blockiert.
- **Semantische Guardrails**: KI-Embedding-Lookup wird übersprungen, wenn die Anfrage <3 Zeichen lang ist oder wie eine ID/Zahl aussieht (`/^\d+$/` oder `/^[0-9a-f-]{8,}$/i`).
- **Embedding-Refresh-Hooks**: `fireAndForgetEmbed("tastings", id)` läuft jetzt auch in `updateTasting` (zusätzlich zu `createTasting`); für Whiskies und Distilleries wie zuvor.
- **Verifikation** (live curl gegen die Dev-API): „Lagavullin" (Tippfehler) findet `Lagavulin`; „torfig"/„rauchig" finden den DE-Lexikoneintrag „Torfig / Rauchig"; „Speyside"/„Islay" zeigen Lexikon + 3 Distillerien; mit `x-participant-id`-Admin-Header zusätzlich Whisky `Lagavulin 16` (für „Lagavulin"), Whisky `Uigeadail` (für „ardbeg"), Tasting `Islay Discovery — 8 Legends` für „Discovery"/„Islay" UND für die Whisky-Namen „Lagavulin"/„Uigeadail"/„Laphroaig" (Score 0.58–0.73).
- **Status Embeddings**: `OPENAI_API_KEY` als Secret gesetzt, aber Konto ohne Credits → alle Backfill-Calls 429. Endpoint setzt `embeddingUsed:false` und nutzt nur die lexikalische Hälfte. Sobald Credits verfügbar sind: `npx tsx scripts/embed-backfill.ts`, danach werden Query- und Row-Embeddings automatisch aktiviert.

### Auto-Handout Generator (Task #701)
Hosts can auto-generate a research-backed handout per tasting. Implementation:
- **Schema** (`shared/schema.ts`): three new tables — `distillery_profiles` (per-distillery encyclopedia cache, keyed by lowercased name), `whisky_profiles` (per-bottling cache, keyed by `wb:<id>` or `<distillery>|<name>`), and `tasting_auto_handouts` (per-tasting binding with selection, chapter order, image picks, language/tone/length, visibility). Shared JSON types: `AutoHandoutChapter`, `AutoHandoutSource`, `AutoHandoutImage`, `AutoHandoutSelection`, plus `AUTO_HANDOUT_CHAPTER_TYPES` constant (8 distillery chapters: Steckbrief, Geschichte, Stil, weniger_bekannt, Geheimtipps, Stories, Aktuelles, Kontroversen — and 4 whisky chapters: Steckbrief, Besonderes, Sensorik, Sammler).
- **Server pipeline** (`server/auto-handout/`): `research.ts` fetches Wikipedia DE+EN summaries + Commons media-list for images, plus web search via existing `lib/onlineSearch.ts` for blogs/news/forums, with timeout-safe fetch and HTML stripping. `condense.ts` calls OpenAI per chapter with structured JSON prompts that enforce inline `[n]` citations and a `confidence` field (high|medium|low). `index.ts` orchestrates ensure/refresh of profiles, per-chapter regeneration, and `assembleHandout(tastingId)` which joins tasting whiskies → cached profiles → ordered chapter refs with the host's selection overrides applied.
- **Routes** (`server/routes.ts`): `GET/POST/PATCH/DELETE /api/tastings/:id/auto-handout`, plus `/auto-handout/generate` (background job; returns immediately and polls), `/auto-handout/regenerate-chapter`, `/auto-handout/refresh-distillery`, and `GET /api/distillery-profiles` for the source library. New AI feature id `auto_handout` registered in `ai-settings.ts`.
- **Frontend**: `AutoHandoutManager` (host UI) renders next to the existing `TastingHandoutManager` in `LabsHost.tsx` — language/tone/length/visibility selectors, generate button with progress polling, per-chapter checkbox/edit/regenerate (tone+length), distillery image picker with license hints, and PDF export. `AutoHandoutViewer` renders in `LabsLive.tsx` as a collapsible "Zusatzinfos der App" block below any host-uploaded handout (the upload remains primary content). Visibility supports `always` or `after_first_reveal`.
- **PDF** (`client/src/components/auto-handout-pdf.ts`): jsPDF generator grouped by subject with per-group sources, confidence markers (`~`/`(?)`), and a closing notice page about source verification. Uses `saveJsPdf` from `lib/pdf.ts`.
